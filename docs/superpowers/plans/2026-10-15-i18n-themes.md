# Inventure Communications i18n, RTL & Themes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add English/Arabic locale routing with RTL, light/dark/system theming, and locale-aware CMS mock content derived from the company profile.

**Architecture:** Hybrid `next-intl` (UI chrome) + CMS `fetch*(locale)` (content). Routes live under `src/app/[locale]/`. Next.js 16 uses `src/proxy.ts`. Themes via `next-themes` (`class` + `data-theme`) and semantic CSS variables. Logical Tailwind utilities for RTL.

**Tech Stack:** Next.js 16.4.1, TypeScript strict, Tailwind CSS v4, `next-intl`, `next-themes`, Framer Motion, Vitest

## Global Constraints

- Spec: `docs/superpowers/specs/2026-10-15-i18n-themes-design.md` (Approved)
- Locales: `en` | `ar`; URLs `/en/...` and `/ar/...`; `localeDetection: true`
- Proxy file: `src/proxy.ts` (not `middleware.ts`)
- Brand display: Latin “Inventure Communications” in both locales (`<bdi>` in Arabic strings)
- Numerals: Western digits
- Theme UI: light/dark/system only; `[data-theme='desert']` CSS-ready, no Header control
- Insights/case studies: soft homepage placeholders; CMS stubs return `[]`
- 7 services + 3 ESG from company profile; mock model `{ en, ar }` per field
- Cache tags: `services:{locale}`, `service:{locale}:{slug}`, etc.; expand bare `services` → both locales
- Tailwind v4 must define `@custom-variant dark (&:where(.dark, .dark *));`
- No physical direction utilities (`ml-`, `mr-`, `pl-`, `pr-`, `left-`, `right-`, `text-left`, `text-right`, `border-l`, `border-r`)
- Arabic copy is AI-drafted pending human review
- Work on branch `feat/inventure-website-bootstrap` (or a follow-on branch from it)

`src/i18n/request.ts`:

```ts
import { getRequestConfig } from "next-intl/server";
import { hasLocale } from "next-intl";
import { routing } from "@/i18n/routing";

export default getRequestConfig(async ({ requestLocale }) => {
  const requested = await requestLocale;
  const locale = hasLocale(routing.locales, requested)
    ? requested
    : routing.defaultLocale;

  let messages;
  try {
    messages = (await import(`../../messages/${locale}.json`)).default;
  } catch {
    messages = (await import(`../../messages/en.json`)).default;
    if (process.env.NODE_ENV === "development") {
      console.warn(`[i18n] Falling back to en messages for locale=${locale}`);
    }
  }

  return { locale, messages };
});
```

`src/proxy.ts`:

```ts
import createMiddleware from "next-intl/middleware";
import { routing } from "@/i18n/routing";

export default createMiddleware(routing);

export const config = {
  matcher: ["/((?!api|trpc|_next|_vercel|.*\\..*).*)"],
};
```

Wire next-intl plugin in `next.config.ts` per current next-intl docs for Next 16 (typically `createNextIntlPlugin()` wrapping the config). Keep existing Tailwind turbopack CSS rules; do not re-enable `cacheComponents`.
